# Dead Air x64

Порт мода **Dead Air** — форка Call of Chernobyl для S.T.A.L.K.E.R.: Call of Pripyat — с 32-битного
движка на **[OpenXRay](https://github.com/OpenXRay/xray-16)**: 64 бита, DirectX 11, современные
апскейлеры.

Публикуется с разрешения автора оригинального мода.

> **English:** a 64-bit port of the *Dead Air* mod to the OpenXRay engine (DX11), with motion vectors,
> DLSS / FSR 2 / FSR 3 / XeSS and a rebuilt options menu. Engine changes are marked `[DA_PORT]` in the
> sources. Documentation is in Russian, in [`da_port/docs/`](da_port/docs/README.md).

---

## Что здесь сделано

**Апскейлеры и сглаживание.** Честные векторы движения для всей геометрии, включая скелетную
анимацию, и на них — **DLSS**, **FSR 2**, **FSR 3**, **XeSS** и собственная TAA. Выбираются одним
пунктом в меню; одновременно работает ровно один — движок это гарантирует сам. FSR 2 при рендере в
70% даёт около **+50 fps**.

**Производительность.** Найдены и закрыты три источника тормозов, каждый ценой больше, чем все
настройки графики вместе взятые:

| | было | стало |
|---|---|---|
| сталкеры с недостижимой целью искали путь каждый кадр | 75 fps | **531 fps** |
| нет потолка теневых источников: 61 лампа = 61 прогон сцены | 9.65 мс | **3.75 мс** |
| дальность каскадов солнца 180 м | 130 fps | **240–500 fps** |

**Игровая логика.** Перенесены правки автора: слоты инвентаря, детекторы и счётчик Гейгера, зоны,
защита костюмов и шлемов, торговля, переносные источники света, система состояния актёра, вес
снаряжения, КПК.

**Интерфейс.** Отдельная вкладка «Производительность» с общими пресетами, перебранное меню видео,
подписи значений у ползунков.

Всё, что отличает порт от чистого OpenXRay, помечено в исходниках маркером `[DA_PORT]` с объяснением
**почему**, а не что. Полный список — 920 правок в 199 файлах — собирается из этих меток:

```bash
python da_port/docs/_regen_changes.py
```

месте», а не «данных нет». Каждая из этих трёх стоила отдельной ночи.

## Сборка

Тулчейн — MinGW (MSYS2). Быстрая сборка одной цели около шести секунд:

```bash
bash _build_fast.sh xrRenderPC_R4
```

Перед первой сборкой нужны сторонние SDK — в репозиторий они не входят:

```bash
git clone --depth 1 https://github.com/NVIDIA/DLSS.git Externals/nvngx
git clone --depth 1 https://github.com/intel/xess.git Externals/xess
```

⚠️ Правка общего заголовка требует пересборки **всего**: иначе часть модулей останется с прежним
представлением о размере класса, игра соберётся, запустится и упадёт в неожиданном месте.

## Что не доделано

Пишем честно, чтобы никто не потратил вечер зря:

- **мерцание земли под острым углом** при включённой реконструкции. На родном разрешении чисто, на
  FSR 3 слабее в 5–6 раз. Статика пишет в буфер скоростей, но значение выходит нулевым: две матрицы,
  из которых считается вектор, в шейдере совпадают. Причина известна, лечение — нет;
- **дрожь растительности** на границе дальности детализации;
- **XeSS на DX11 работает только на Intel Arc** — ограничение самой библиотеки;
- **генерации кадров нет и не будет**: она требует асинхронных аппаратных очередей, которых в
  DirectX 11 не существует. Ограничение API, а не наше решение.

Подробности и списки уже отпавших версий — в [05_ROADMAP](da_port/docs/05_ROADMAP.md) и
[06_QUESTIONS](da_port/docs/06_QUESTIONS.md).
