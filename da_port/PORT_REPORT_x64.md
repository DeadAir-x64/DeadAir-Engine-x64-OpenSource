# Dead Air → x64 (OpenXRay): отчёт по работе после декомпиляции

_Дата: 2026-07-24_

Кратко: порт мода **Dead Air** (закрытый x86 на базе Call of Chernobyl) на **x64** через движок
**OpenXRay**. Исходников DA-движка нет — поведение восстанавливаем декомпиляцией оригинальных
x32-бинарников (Ghidra) и переносим движковые правки в порт. Данные (конфиги/скрипты/ассеты) держим
**1:1 с оригиналом** — правим только движок C++ (и при крайней необходимости — точечно порт-конфиги,
всё задокументировано).

---

## 0. Что было на входе

- Порт (правим): `xray-16\src\` — OpenXRay + WIP x64-порт.
- Оригинал x32 DA (полный движок, render-DLL): `Dead Air\engine_backup_32bit_orig\`.
- Игра (деплой): `Dead Air\` — лаунчеры `Dead Air DX11.cmd` (-r4), `Dead Air GL.cmd` (-rgl).

Базовый факт: **данные порта = данные DA байт-в-байт** (сдиффлено). Значит весь пробел между
портом и оригиналом — это **движок C++**, ничего в gamedata портировать не нужно.

---

## 1. Декомпиляция — вся сделана

- **16 модулей движка декомпилировано, 50 925 функций, 0 отказов.**
  xrGame, xrEngine, xrCore, xrPhysics, xrSound, xrCDB, xrNetServer, xrParticles, xrGameSpy, xrAPI,
  xrRender_R1/R2/R3, xrCPU_Pipe, xrXMLParser, xrD3D9-Null.
- **Именование функций** (RTTI + assert-строки + binref от x64-эталона): xrGame ~3151 названо,
  рендер R1/R2/R3 ~13-14%, всего ~6800+.
- Пакет инструментов + результаты: `ghidra_codex_handoff\` (Ghidra 12.1.2, проект `DA_x32` со всеми
  импортированными модулями, скрипты, `decomp_out\<module>\chunk_*.c` + `_INDEX.tsv`, `.bat`-раннеры).
- **Gap-анализ** движковых правок: `_FULL_GAP.md` (949 DA-only строк, 129 config-ключей),
  `_WORKORDER_keys.md` (A=43 CoC-штатных, B=73 DA-добавления).

> Декомпилят xrGame лежит в `decomp_out/xrGame.dll/` (**с** `.dll` в имени папки): 142 чанка + `_INDEX.tsv`
> (addr→имя→строк→чанк). Папка `xrGame/` без `.dll` — пустая.

## 2. Инфраструктура сборки/деплоя

- Конфиг = **Release** (NDEBUG). **Сборку ускорил с ~15 мин до ~6 сек** (ccache + `-Og` + LTO off):
  `bash _build_fast.sh <target>`. Тёплый кэш: правка `.cpp` ~2-13 с; правка широкого хедера
  (Actor.h) — near-full rebuild ~140 с.
- Таргеты: `xrGame`, `xrEngine`, `xrRenderPC_R4` (GL = `xrRender_GL`). Правка ENGINE_API-глобала в
  xrEngine требует пересборки+деплоя xrEngine.dll + всех потребителей.
- Деплой: копировать нужные `.dll` из `xray-16\bin\AMD64\Release\` в `Dead Air\bin\`.
- Шейдер-кэш `appdata\shaders_cache_oxr\r4\` чистить ТОЛЬКО при смене шейдер-дефайнов (не для CPU-правок).
- **Дебаг-спавн не требует Mixed/DEBUG-билда**: `g_spawn`, `g_spawn_to_inventory`, `run_script` и т.п.
  гейтятся `#ifndef MASTER_GOLD`, а `MASTER_GOLD` есть только в `ReleaseMasterGold` → в нашем `Release`
  команды уже вкомпилены. (`-dbg` движком игнорируется; полный DEBUG-toggle/ImGui — только Mixed-конфиг.)

## 3. Движковые фиксы в порте

### 3.1 Критичные креши

| # | Фикс | Суть |
|---|------|------|
| ✅ | **Креш ALife-реестра «спавн у торговца»** | NPC через `xr_gather_items` спавнит артефакт сразу attached в инвентарь → предмет не в мировом реестре, но `remove()` ассертит (`safe_map_iterator:53`). Сток-баг CoC, не регресс. Фикс: `CALifeGraphRegistry::remove` толерантен к отсутствующему объекту. **Подтверждено: 7+ артов у NPC, 2399 parented-спавнов, 0 крашей.** |
| ✅ | **Креш Опции→Видео (`cap_color_correction`)** | DA-скрипт `ui_mm_opt_video.script` ссылается на ноды (свои слайдеры цветокоррекции), которых нет в загруженном `ui_mm_opt.xml` порта → фатал `InitWindow`. Фикс: `CScriptXmlInit::Init*` пропускают отсутствующую ноду (гвард + Msg) вместо краша — **общий фикс класса «DA-скрипты vs портовые UI-XML».** |

### 3.2 Рендер (R4 / DX11)

| # | Фикс | Суть |
|---|------|------|
| ✅ | **R4 «чёрный/тёмный мир» → играется** | Loose стоковые OpenXRay-шейдеры в `gamedata\shaders\r2\|r3` перекрывали архивные самодостаточные DA-шейдеры (VFS: loose > архив) → ломалась компиляция `lmodel.h` (`undeclared L_RANGE`), движковые инжекты-заглушки с нулями (`H_TERR=0`) убивали hemisphere-свет. Фикс: loose r2/r3 → бэкап, все инжекты убраны из `r4_shaders.cpp`, кэш очищен. **⚠️ Нельзя класть `shaders\r2\|r3` обратно в игру — снова сломает R4.** |
| ✅ | **Капли дождя на визоре (lens-water)** | Анимация протирки маски рукой стирала «пустоту» — капли в R4 не рендерились. HLSL капель существует в `combine_1.ps` DA, но порт (а) не инжектил дефайн `USE_LENS_WATER`, (б) не биндил uniform `lenswater`. Фикс: `options.add("USE_LENS_WATER","1")` + биндинг в проходе **E[0]** (combine_1, не combine_2/tonemap), значение `max(ps_r2_lenswater_val, ps_r2_lenswater)`. В дожде `dinamic_hud` сам поднимает `r2_lenswater_val` → капли + протирка. **Подтверждено.** |

### 3.3 Геймплей-механики

| # | Фикс | Суть |
|---|------|------|
| ✅ | **nearwall** — отвод оружия у стены | Weapon-collision HUD FOV. Глобал `g_hud_fov_current` (ENGINE_API), forward RayPick → clamp дистанции → lerp FOV с экспон.сглаживанием. Live-тюнинг cvar'ами (`hud_nearwall`, `_dist_min/max`, `_target_fov`, `_speed`). Дефолтно ВКЛ. **Подтверждено.** |
| ✅ | **hold-breath + DA aim-sway** | В прицеле удержание ACTION ускорения (`mstate & mcAccel`, ребинд-безопасно) домножает zoom-инерцию на `breath_koef` (=0.02). Раз-заглушен `SetActorZoomInertion` → разброс от `psy_health` (сигареты снижают раскачку). **Подтверждено.** |
| ✅ | **Цена по состоянию предмета** (`trade2.cpp`) | Порт хардкодил показатель `pow(cond*0.9+0.1, 0.75)`, DA читает его из `[trade] buy_condition_koeff` (=3) — изношенные вещи дешевеют сильнее. |
| ✅ | **Volumetric-свет аномалий** (`CustomZone`) | Порт имел только on/off; добавил чтение `light_volumetric_quality/intensity/distance` (рендер уже поддерживал сеттеры). |
| ✅ | **Колбэк `take_item_from_ground`** | DA-скрипты регистрируют колбэк подбора с земли (звук + новость с именем предмета), порт его не имел. Добавлен enum + биндинг + вызов в `GE_OWNERSHIP_TAKE` (только подбор с земли, не торговля/ящик). |
| ✅ | **Малфункции оружия (u32-маска) + `condition_avail`** | Поле `m_weapon_condition_type` в порте было **u8**, а DA юзает как **32-битную маску поломок** (биты 20-31 = типы джемов: прицел/глушитель/подствол/firemode). Биты 8-31 резались → оружие в порте **не могло получить ни одной поломки**, вся система малфункций была мертва. Фикс u8→u32 включил её целиком (enforcement скриптовый: `death_manager`/`xr_wounded`/`ui_itm_repair`/`dxr_scopes`, данные 1:1). +UI: секция «Состояние:» в тултипе оружия (`st_condition_type` по битам). |
| ✅ | **Переносные источники света + «Установить»** | Фонарь/палочка/зажигалка (раз-заглушены `torch_set_*` в `CTorch`, убран гейт стейта, пофикшен omni-флуд) + керосинка (world-light). Режим превью «Установить» (призрак за прицелом + confirm-клик) на общем функторе — работает у всех 7 предметов. **Подтверждено.** |
| ✅ | **ПНВ (ночное видение)** | Не включался у костюмов с встроенным ПНВ. Причина: клавишу `kNIGHT_VISION` обрабатывали **ДВА хендлера** — C++ (`SwitchNightVision`, наследие ванильного CoP) И Lua (`itms_manager.script`) → двойной тоггл гасил сам себя. Фикс: убрал C++-хендлер, отдал клавишу скрипту (как в DA). Data-driven (`nightvision_sect`) — работает ровно на задуманных автором костюмах. **Подтверждено.** |

### 3.5 Визуал (последняя сессия)

| # | Фикс | Суть |
|---|------|------|
| ✅ | **Голова актёра** (тень/труп/голый/в костюме) | DA-костюмы прописывают `actor_visual = actors\legs\<outfit>.ogf` — это **безголовые модели «от 1-го лица»** (ноги+торс, без рук/головы). ### 3.6 Детектор 3D-UI (`hud_ui_*`)

- Elite/Scientific (Велес/Сварог) — 3D-экран с метками артефактов **работает**, подтверждено юзером.
- Реализован DA-механизм `hud_ui_*` для simple-детектора (не было ни в порте, ни в CoC — чистая
  DA-специфика; сам `hud_ui_3d.xml` в данных DA отсутствовал, создан). Класс `CUIArtefactDetectorHudUI`

## 4. Что осталось / роадмап

- **Фаза B (авторские добавления DA) — мелкие фичи исчерпаны.** Чистых безопасных feature-extend
  почти не осталось (trade/volumetric/take_item были ими).
- **Мёртвое, не портировать:** `condition_coeff` (движок только пишет +0x830, никто не читает — ни
  движок, ни скрипты; заброшенный хук).
- **Ждёт in-game теста:** малфункции оружия (u32) + секция «Состояние» в тултипе.
- **Хвосты:** `gid_` quick-switch (нет данных о составе групп оружия DA).
- **Безвредный спам в логе:** `Failed to find compiled constant buffer` (~7820×) — деструктор
  `dx11ConstantBuffer` чистит из всех контекстов, буфер в одном → лог для остальных. Рендер не ломает,
  глушится правкой деструктора (нужен ребилд render-модуля).

## 5. Ключевые уроки (грабли)

1. **Gap-лист шумный.** `grep` по литералу ключа ненадёжен: порт часто читает ключи **динамически**
   (`strconcat`, лямбды `r_range`) — литерала в исходнике нет, а ключ читается. Перед правкой —
   **читать функцию-читатель порта**, не грепать литерал. Многие «пробелы» окажутся уже сделаны
   (весь кластер ворона, gradient_*, use_ammo_belt…).
2. **«Мёртвое поле движка» ≠ мёртвая фича.** DA часто выносит логику в **скрипты**, читающие ключ из
   конфига напрямую (`system_ini():r_string_ex(sec,"key")`), минуя движковое поле. Пример:
   `condition_avail` живой — им рулит `items_condition.script`. Всегда проверять `vfs_scripts` на
   `r_*_ex(section,"ключ")`.
3. **Скан архивов ≠ что реально грузит движок.** Статический скан `.xdb` может «не найти» ассет,
   который игра находит через VFS/патч-архивы. Истина = наблюдение в игре, не скан xdb.
4. **Двойная обработка.** При «фича была в DA, конфиг совпадает, а не работает» — искать **два
   хендлера** на одно событие (порт=OpenXRay-C++ + DA-скрипт). C++-лог в точке действия даёт
   ground-truth за 1 итерацию (Lua-лог капризен: VM кешируется до рестарта exe).
5. **legs-модели DA = вид от 1-го лица** (ноги+торс, без рук/головы) — непригодны как третьеличная
   модель. Для тени/трупа — только полные NPC-модели фракций.

## Приложение: файлы, которые нельзя трогать/потерять

- `da_port_actor_visual.ltx` (маппинг костюм→модель) — новый **port-конфиг**, не правка оригиналов DA.
- `shaders_loose_stock_backup\` — сюда вынесены стоковые loose r2/r3; **не возвращать в игру**.
- `bin\dxgi.dll` (5157144 б, x64 ReShade) + `bin\ReShade.ini` + `bin\reshade-shaders\`.
- `user.ltx` перезаписывается игрой на выходе — правь при **закрытой** игре.

_Все правки — в движке порта (`xray-16\src`) либо в отдельных port-конфигах; оригинальные данные DA
не тронуты (1:1)._
