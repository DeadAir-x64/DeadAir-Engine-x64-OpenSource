# Регламент: радужные разводы на металле под апскейлером

> ## ✅ ЗАКРЫТО. Замеры по этому регламенту больше не нужны
>
> Симптом снимается настройкой **`r__tf_aniso 16`**, и та же настройка закрыла мерцание земли под
> острым углом — дефект оказался один. Корень: под апскейлером mip LOD bias сдвинут в минус, а при
> отрицательном сдвиге трилинейная фильтрация недосэмплирует, и вместо мыла получается высокочастотная
> крупа. Разбор — в `09_UPSCALERS.md`, раздел «Мерцание земли под острым углом».
>
> Документ оставлен как **история поиска**: раздел 5 «Что уже исключено замерами» экономит время,
> если похожий артефакт всплывёт снова, а раздел 0 «Дисциплина замера» годится для любой серии
> замеров в этом проекте. К релизу остаётся решить, что делать с диагностическими крутилками
> (`r__detail_*_fix`, `r__detail_debug`, `r__wind_scale`) — вычистить или оставить.

Симптом (историческое описание): на металле (бочки, машины) и на дальних текстурах под FSR 2
появляется переливающаяся цветная крупа, которая **меняется каждый кадр**. Без апскейлера картинка
чистая.

Этот документ — процедура замера, а не описание фикса. Инструмент в сборке уже есть и по умолчанию
выключен: все крутилки в нуле, шейдер при этом побитово совпадает с исходным.

## 0. Дисциплина замера (читать первым)

За день на этом баге было потеряно несколько заходов, и **все** потери — из-за состояния консоли,
а не из-за неверных гипотез. Поэтому:

1. **Перед серией — сбросить базу.** Значения от прошлых проб оседают в `appdata\user.ltx` при выходе
   и молча искажают следующий замер.
2. **Проверять состояние по файлу, а не по памяти.** Открыть `Dead Air\appdata\user.ltx` при закрытой
   игре и убедиться глазами.
3. **Один замер — одно изменение.** Два одновременно — и результат не читается.
4. **Если что-то «не изменилось» — сначала проверить, доехала ли сборка.** Деплой падает молча, если
   игра запущена и держит DLL.

### Что когда вступает в силу

| Что меняем | Когда действует |
|---|---|
| `r__detail_debug`, `r__detail_*_fix` | **сразу**, прямо в игре |
| `r2_gloss_factor`, `r2_parallax_range` | **сразу** |
| `r2_detail_bump`, `r2_steep_parallax` | **перезаход на уровень** (меняется вариант шейдера) |
| `r__upscaler`, `r__upscaler_quality`, `r__fsr2`, `r__fsr3`, `r__xess`, `r__dlss` | **перезапуск игры** (контекст строится при старте рендера) |
| `r__motion_vectors` | **перезапуск игры** (флаг защёлкивается при старте рендера) |
| правка `.ps`/`.vs`/`.h` шейдера | **очистка** `appdata\shaders_cache_oxr` при закрытой игре |

## 1. Сброс базы

При **закрытой** игре стереть кэш шейдеров не нужно — шейдеры не меняются. Запустить игру и ввести:

```
r2_detail_bump on
```
```
r2_steep_parallax on
```
```
r2_parallax_range 75
```
```
r2_gloss_factor 6
```
```
r__detail_debug 0
```
```
r__detail_gloss_fix 0
```
```
r__detail_normal_fix 0
```
```
r__detail_albedo_fix 0
```
```
r__reactive_foliage 0.5
```
```
r__motion_vectors 0
```

Затем **выйти из игры полностью** (часть значений применяется только при старте рендера), зайти
в Настройки → Видео и выставить **Масштабирование = FSR 2.0**, качество любое. Один апскейлер, не два.

**Проверка базы.** При закрытой игре открыть `Dead Air\appdata\user.ltx` и убедиться, что там:
`r2_detail_bump on`, `r2_gloss_factor 6.`, `r2_parallax_range 75.`, `r__detail_debug 0`,
все три `r__detail_*_fix 0.`, и включён ровно один апскейлер.

**Контроль симптома.** Встать у знакомого объекта (бочка на тележке) и убедиться, что разводы
на месте. Если их нет — дальше мерить нечего, состояние опять не то.

## 2. Замер A: по какой ветке идёт поверхность

Детальная текстура применяется двумя разными способами, и лечатся они по-разному. Эти режимы
работают на лету.

```
r__detail_debug 6
```
Зелёным заливаются **все бампованные поверхности**. Это контроль: если объект не позеленел —
он вообще не проходит через `sload.h`, и весь дальнейший разбор к нему неприменим.

```
r__detail_debug 3
```
Красным — только те, где работает ветка **detail-bump** (деталь перебивает нормаль и множит глянец).

```
r__detail_debug 7
```
Синим — ветка **без бампа** (деталь красит альбедо цветной текстурой и множит глянец).

Красный и синий взаимоисключающие. Записать, какого цвета проблемный объект.

> ⚠️ Смысл имеет только при `r2_detail_bump on`. При выключенном флаге `USE_TDETAIL_BUMP` не определён
> ни для чего, все поверхности обязаны оказаться синими, и замер не значит ничего. На этом уже обожглись.

```
r__detail_debug 0
```
Вернуть перед следующим шагом.

## 3. Замер B: какая половина виновата

Подбирать числа не нужно — эти режимы выключают вклад целиком.

**Если объект оказался КРАСНЫМ** (ветка detail-bump):

```
r__detail_debug 4
```
Убирает вклад детали **в нормаль**. Разводы ушли?

```
r__detail_debug 5
```
Убирает вклад детали **в глянец**. Разводы ушли?

**Если объект оказался СИНИМ** (ветка без бампа):

```
r__detail_debug 8
```
Убирает вклад детали **в альбедо**. Разводы ушли?

```
r__detail_debug 9
```
Убирает вклад детали **в глянец**. Разводы ушли?

Результат этого шага — ответ вида «виновата нормаль» или «виновато альбедо». На нём заканчивается
поиск и начинается настройка.

## 4. Замер C: подбор порога

Затухание считается по тому, **насколько быстро деталь меняется от пикселя к пикселю** — то есть
гасится только там, где текстура мельче пикселя и всё равно не разрешима. Вблизи, где деталь честно
видна, авторский вид не трогается. Величину этой «скорости» никто заранее не знает, поэтому её видно
на экране.

Включить показ веса для нужной половины:

```
r__detail_debug 1
```
красит вес, применяемый к **нормали** (пара к `r__detail_normal_fix`)

```
r__detail_debug 2
```
красит вес, применяемый к **глянцу** (пара к `r__detail_gloss_fix`)

Чёрное — не трогаем вообще, белое — гасим полностью. Теперь крутить соответствующую крутилку
(диапазон 0..4096, начать с 8, дальше 64, 512):

```
r__detail_normal_fix 64
```
```
r__detail_gloss_fix 64
```
```
r__detail_albedo_fix 64
```

**Что искать:** значение, при котором проблемный металл заметно светлеет, а доски забора, кирпич
и земля рядом остаются тёмными. Это и есть рабочий порог: лечим ровно те поверхности, которые
алиасятся, и не трогаем остальные.

> ⚠️ **Известное ограничение нынешней меры (замерено 26.07).** При значении 64 белым становится
> ВСЁ — деревья, дома, металл. То есть `length(ddx)+length(ddy)` по детали велика везде и проблемные
> поверхности от обычных не отличает: крутилка работает как рубильник, гасящий деталь глобально,
> а это порча картинки ради апскейлера. Меру надо будет заменить на избирательную — но сначала
> нужен результат замера B, потому что от него зависит, что именно измерять: разброс нормали
> или отклик блика.

Затем:

```
r__detail_debug 0
```

и посмотреть на результат уже в нормальной картинке. Если разводы ушли, а вблизи ничего не потеряло
детализацию — значение найдено, скажи его, я зашью дефолтом и уберу отладочные режимы.

## 5. Что уже исключено замерами (не перепроверять)

| Версия | Как отвергнута |
|---|---|
| Резкость / RCAS | `r__upscale_sharpness 0` не помогает |
| Смещение мипов | `r__taa_mipbias 0` не помогает |
| Масштаб рендера | разводы есть и при 100 % |
| Крутой параллакс | `r2_steep_parallax off` не помогает |
| Реактивная маска | `r__reactive_foliage 0` не помогает |
| Векторы движения | у объекта в покое ровный ноль, разводы при этом на месте |
| Дальность детали | `r2_parallax_range 5` только сужает область — значит артефакт живёт в HQ-варианте |

Общий вывод из таблицы: артефакт создаёт **детальная текстура** внутри HQ-варианта шейдера. Осталось
определить, какой именно её вклад, — это и есть замеры A и B.

## 6. Диагностика, если что-то ведёт себя странно

**Экран трясётся.** Проверить, что включён ровно один апскейлер, и что `r__motion_vectors 0`.
Режим 3 у `r__motion_vectors` пишет в буфер скоростей клейма шейдеров вместо векторов — апскейлер
получает «движение» порядка 50 пикселей за кадр и тащит историю с другого конца экрана. В логе на
этот случай теперь есть предупреждение.

**Правка шейдера не применяется.** Кэш. Закрыть игру, удалить `appdata\shaders_cache_oxr`, запустить —
первый заход на уровень будет долгим.

**Всё стало матовым и плоским.** Проверить `r2_gloss_factor` — должно быть 6 (авторское). Ноль теперь
недостижим, минимум 1, но 2 уже заметно портит металл.

**Ничего не меняется вообще ни при каком значении.** Сначала `r__detail_debug 3` и `6`: если ничего
не красится, значит константа не доходит до шейдера либо поверхность не идёт через `sload.h` —
это принципиально другая проблема, чем «число слишком маленькое», и без этой проверки они неразличимы.
