# Регламент выпуска

Один документ на весь путь: от «дерево зафиксировано» до «игрок прислал лог, и лог разобран».
Раньше эта процедура описывала только движок — и ровно поэтому 11.08.2026 тестерам уехал
**неполный выпуск**: движок целиком, а из двух дней правок по Lua — ничего.

⛔ **Правило, из которого всё остальное следует.** Выпуск — это не «собранный движок». Выпуск —
это **всё, что менялось с прошлого выпуска**: модули, игровые файлы, настройки по умолчанию,
снимок символов и текст. Пропуск любой части не виден ни по сборке, ни по запуску: и то и другое
проходит честно.

## 1. Порядок

### Шаг 1. Зафиксировать оба дерева

```bash
git -C "D:/Dead Air/xray-16" status --porcelain --untracked-files=no
git -C "D:/DeadAir_Update"   status --porcelain --untracked-files=no
```

Пусто в обоих — можно собирать. Сборка из грязного дерева получает метку `-dirty` и становится
невоспроизводимой: восстановить по ней исходники нельзя, а значит и краш по ней не разобрать.

⚠️ Непроиндексированные файлы намеренно не учитываются: в рабочем дереве их всегда сотни.

⛔ Метка `-dirty` считается по корневому репозиторию, а **грязный подмодуль в нём виден**.
Фиксировать снизу вверх: сперва подмодули, потом корень.

### Шаг 2. Собрать

```bash
cd "D:/Dead Air"
cmake -S xray-16 -B xray-16/build_release   # ОБЯЗАТЕЛЬНО, см. ловушку 1
bash _build_release.sh all
```

⛔ **Не прерывать.** Прерванная релизная сборка оставляет DLL нулевого размера, а `ninja` при
следующем запуске рапортует «finished 0s» и ничего не делает.

⚠️ Выходной каталог у релизной и быстрой сборок **общий**. Первая же отладочная сборка перетрёт
релизные DLL, поэтому шаги 3 и 4 идут сразу.

В выводе конфигурации должно быть непустое:

```
-- XRAY_GIT_SHA:          07d02d134466
```

`no-git` или пусто — остановиться: `git` не виден `PATH` сборочного скрипта, и лог игрока будет не
с чем сопоставить.

### Шаг 3. Снимок символов

Делается сам, в конце `_build_release.sh`. Вручную — `bash _archive_symbols.sh`.

Складывает в `D:/DA_symbols/<ревизия>/`: карты линковщика `*.map.gz`, `maps.txt` (когда собрана
каждая), `modules.txt` (размер файла, размер образа, sha256), `commit.txt`, каталог `shipped/` с
самими отгружаемыми модулями и текст выпуска. 88 МБ карт сжимаются до 5.7 МБ — хранить бессрочно.

⛔ **Полный снимок получается только при полной сборке** (`all`). Иначе часть карт останется от
прежних сборок, и разбор по ним даст **чужое имя функции** — это хуже отсутствия разбора.

⚠️ Пометка «СТАРЕЕ» в `maps.txt` считается от самой новой карты в снимке и на неполной пересборке
**врёт**: модуль, который не менялся, честно сохраняет свою прежнюю карту. Заслон сравнивает
карту с ЕЁ модулем, а не с соседними.

### Шаг 4. Разложить в игру

Копировать в `Dead Air/bin` **только изменённое**.

⛔ Массовое копирование уже роняло FPS с 242 до 130: перф-критичные модули должны быть из релизной
сборки (`-O3` + межмодульная оптимизация), а не из быстрой (`-Og`).

⛔ Игру запускает `xrEngine.exe`, а сборка делает `xr_3da.exe`. Копию надо создать явно, иначе
запустится **старый** движок при новых DLL. Заслон сверяет их хеши.

⚠️ Перед копированием убедиться, что игра закрыта.

### Шаг 5. Свести игровые файлы в отгрузку

**Тот шаг, которого не было.** Всё, что правилось в `Dead Air/gamedata`, обязано уехать в
`DeadAir_Update/gamedata` — и ровно в том виде, в каком проверялось.

```bash
python "D:/Dead Air/xray-16/da_port/tests/run_tests.py"
```

Проверка `release_shipping` сверяет три дерева по СОДЕРЖИМОМУ:

```
оригинал мода (extracted) -> игра (loose gamedata) -> отгрузка (DeadAir_Update)
```

и требует двух вещей:

1. файл в игре отличается от оригинала мода ⇒ обязан быть в отгрузке с тем же содержимым;
2. файл в отгрузке обязан быть и в игре ⇒ иначе игроки получают то, чего мы не проверяли.

⚠️ **Направление решается содержимым, а не датой.** `sim_squad_scripted.script` в игре имел дату
свежее репозиторной и при этом потерял защиту от освобождённого отряда.

Файл, который сознательно не отгружается, вносится в `da_port/tests/lint/not_shipped.txt` с
причиной. Пустой список — норма.

### Шаг 5а. Наполнить `shipped/` в снимке

**Шага не было, и заслон на нём краснеет.** Снимок символов делается в конце сборки, когда модули
ещё НЕ разложены в игру, поэтому каталога `shipped/` в нём нет, и заслон честно отвечает
«не с чем сверить отгруженные модули». Делать после шага 4:

```bash
python - <<'EOF'
import os, shutil
SNAP = r"D:\DA_symbols\<ревизия>\shipped"
GB   = r"D:\Dead Air\Dead Airin"
# Состав берётся из предыдущего снимка: наши модули + da_ngx.dll + xrEngine.exe/xr_3da.exe.
os.makedirs(SNAP, exist_ok=True)
for f in os.listdir(r"D:\DA_symbols\<прошлая ревизия>\shipped"):
    src = os.path.join(GB, f)
    if os.path.isfile(src):
        shutil.copy2(src, os.path.join(SNAP, f))   # ⛔ именно copy2, см. ловушку 12
EOF
```

Зачем он нужен: по логу игрока надо восстановить, какие именно двоичные файлы у него работали.
Карты линковщика этого не дают — они от СБОРКИ, а разложить можно не всё и не сразу.

⚠️ Заслон сверяет `shipped/` с игрой по хешу. Если после наполнения что-то пересобрать и
переложить — наполнить заново.

#### Что кладётся в `DeadAir-x64-installer.zip`

Разобрано по коду `install.ps1` 19.08.2026. **Коду нужен ровно один файл — сам `install.ps1`**:
единственное обращение к собственной папке во всём скрипте — чтение необязательного `da_token.txt`
(стр. 56–57). Остальное он качает из сети, создаёт сам или ищет в корне уже установленной игры.
Игроку нужны ещё две точки входа и инструкция:

| файл | зачем |
|---|---|
| `install.ps1` | вся работа. ⛔ **BOM обязан сохраниться** — без него Windows PowerShell 5.1 читает кириллицу как ANSI, и все сообщения превращаются в мусор |
| `Установить Dead Air x64.cmd` | точка входа, зовёт `%~dp0install.ps1` |
| `Обновление.cmd` | то же самое; отдельной ветки «обновление» в скрипте нет, режим он определяет сам по метке версии |
| `README.md` | необязателен коду, нужен человеку: требования, откат через `original_x32_backup`, куда слать логи |

Архив **плоский**, без верхней папки: игрок распаковывает его прямо в корень игры.

```bash
python - <<'EOF'
import os, re, zipfile
SRC = r"D:\DeadAir_Update"
OUT = os.path.join(SRC, '_dist', 'DeadAir-x64-installer.zip')
FILES = ['install.ps1', 'Установить Dead Air x64.cmd', 'Обновление.cmd', 'README.md']
BAD = re.compile(rb'ghp_|github_pat_|gho_|ghs_|ghr_|Bearer\s+[A-Za-z0-9_]{20,}', re.I)
for f in FILES:
    hit = BAD.search(open(os.path.join(SRC, f), 'rb').read())
    if hit: raise SystemExit('СЕКРЕТ в %s' % f)
with zipfile.ZipFile(OUT, 'w', zipfile.ZIP_DEFLATED, compresslevel=9) as z:
    for f in FILES: z.write(os.path.join(SRC, f), f)
EOF
```

⛔ **`config/` и `gamedata/` в архив НЕ кладутся, хотя лежат рядом.** Установщик берёт их из
**архива ветки** `main`, а не из своей папки: `config\fsgame.ltx` (стр. 293) и
`config\user.ltx.default` (стр. 358) читаются из распакованного zipball, локальные копии рядом со
скриптом не читаются никогда. Положить `gamedata` в архив вредно вдвойне: распаковав его в корень,
игрок получит устаревшие файлы **до** установки, испортит сравнение шейдеров (кэш снесётся не тот),
и они останутся навсегда — в манифест поставленного они не попадают, а всё, чего в манифесте нет,
уборка считает чужим и не трогает.

Не класть также: `da_token.txt`, `_dist/` (~240 МБ локальных архивов), `appdata/` (состояние
игрока: метка версии и манифест — чужой манифест заставит уборку удалять то, чего игрок не ставил),
`original_x32_backup/`, `.git/` и генерируемый самим установщиком ярлык `Dead Air x64.cmd`
(заранее положенный разойдётся с тем, что пишет актуальная версия).

⚠️ Кириллические имена в zip проверять распаковкой **проводником** (`Shell.Application`), а не
только `Expand-Archive`: это разные распаковщики, и .NET прощает то, на чём проводник спотыкается.
Заодно сверять, что BOM у `install.ps1` пережил упаковку.

#### Что установщик делает на самом деле

Разобрано по коду; знать это нужно, чтобы понимать, до кого правка дойдёт, а до кого нет.

- **Сравнение версий строгое и раннее.** Метка лежит в `<корень игры>\appdata\da_x64_version.txt`,
  сравнивается с `tag_name` последнего выпуска простым равенством — и при совпадении установщик
  выходит **до того, как посмотрит на вложения**. ⛔ Отсюда правило «новый тег обязателен»: заменить
  файл под тем же тегом бесполезно, до игроков это не доедет вовсе.
- **Вложение отбирается по маске `bin*.zip`**, а не «первое подряд». Поэтому второе вложение с
  другим именем безопасно. 🪤 Но маска префиксная: любое будущее `bin_installer.zip`, `bin-full.zip`
  тоже под неё попадёт, и тогда выбор решит порядок GitHub, а не смысл. Имя `bin*` держать
  уникальным за модулями движка.
- **Игровые файлы — из ветки, модули — из выпуска.** Половину забыть некуда: это два разных канала.
- **Установки с нуля нет.** Скрипт требует рядом с собой `database\levels.xdb0` и без него сразу
  отказывается: он ставится **поверх** оригинальной 32-битной игры. Резервная копия
  `original_x32_backup` делается **только при первой установке**.

---

⛔ **Новый тег обязателен даже если движок не менялся.** Установщик сверяет тег выпуска с
установленным (`$installed -eq $latest`) и при совпадении выходит, ничего не скачав. Правка
одних игровых файлов **без нового выпуска до игроков не дойдёт**.

⚠️ `bin` приезжает игроку из **вложения к выпуску**, а `gamedata` и `config` — из архива ветки
`main`. Забыть про любую половину — значит выдать половину обновления.

## 2. Что заслон проверяет

| проверка | что ловит |
|---|---|
| деревья | несведённые правки в обоих репозиториях; расхождение указателей подмодулей — **предупреждением**, не запретом |
| ревизия | метки нет / метка грязная / после метки менялись **исходники** |
| модули | пустые огрызки, отсутствие `xrEngine.exe`, расхождение с `xr_3da.exe` |

| тесты | весь набор `run_tests.py`, включая полноту отгрузки |

**Чего он не проверяет:** картинку, производительность и игровой процесс. Это шаг 8 и живые руки.

## 3. Ловушки

Все проверены на живых выпусках, каждая однажды дала неверный результат молча.

### ⛔⛔ 1. Ревизия вшивается на КОНФИГУРАЦИИ, а не на сборке

`XRAY_GIT_SHA` вычисляется при `cmake -S … -B …` и запекается в `xrCore`. Закоммитили и собрали
без переконфигурации — в бинарнике **чужая** ревизия, и разбор краша поведёт по чужим строкам.
Поэтому шаг 2 начинается с `cmake`.

⚠️ Заслон различает случаи: если после метки правились только документация, тесты и игровые
файлы — это не беда. Беда, если менялись `src`, `Externals`, `cmake` или `CMakeLists.txt`.
🪤 Смена **указателя подмодуля** тоже считается сменой исходников, даже если рабочее дерево
подмодуля не трогали.

### ⛔ 2. `-dirty` считается по корню, а грязный подмодуль в нём виден

Фиксировать снизу вверх.

### ⚠️ 3. «Старая карта» — ложная тревога, признак другой

См. шаг 3. Живой пример (16.08.2026): после ПОЛНОЙ сборки снимок пометил четыре карты как
«старее свежей на 78 ч» — `xrAPI`, `xrLuaJIT`, `xrLuabind`, `xrODE`. Они просто не менялись, и
`ninja` их не перелинковывал. Заслон сверяет карту с ЕЁ модулем и в этом случае молчит: верить
надо ему, а не пометке.

### ⛔ 4. Игру запускает `xrEngine.exe`, сборка делает `xr_3da.exe`

См. шаг 4.

### ℹ️ 5. Порог «меньше 100 КБ» даёт ложное срабатывание

`xrAPI.dll` честно весит 90 КБ. Заслон ловит только явно битое — меньше 20 КБ.

### ⛔⛔ 6. Отгрузка игровых файлов отстаёт молча (11.08.2026)

Последний коммит игровых файлов — 09.08 в 04:46; восемнадцать скриптов правились после, с 09.08
13:48 по 11.08 01:14. Выпуск ушёл тестерам без ускорения КПК (18.5 → 2.1 мс), без кэша condlist,
без семи защит от пустых значений. Ни сборка, ни запуск, ни стенд этого не показывают: **всё
работает, просто не тем содержимым**. Отсюда шаг 5 и проверка `release_shipping`.

Попутно вскрылось ещё три:

- **три скрипта отгружались, а в рабочей установке их не было** — то есть игроки получали то, что
  мы ни разу не запускали;
- **`xr_effects.script`**: перевод перебора ALife на индекс переименовал счётчик, а три строки в
  теле остались на старом `i`. Снаружи цикла это глобал, то есть пустое значение;
  `table.insert(список, nil)` не падает и ничего не кладёт — задача «охота за головами» молча
  не получала цели. Линт `loop_vars` теперь стережёт этот класс;
- **смесь cp1251 и UTF-8** в двух файлах: наши правки занесли одну кодировку в файл с другой.
  Лечится `da_port/tools/fix_script_encoding.py`, стережёт проверка `hygiene`.

### 🪤 7. У стенда счётчики лога МЕНЬШЕ, чем у обычного захода

Проверка из раздела 4 «столько же скриптов, сколько обычно?» на стенде даёт ложную тревогу:
`grep -c 'Loading script'` показал **395 против 445** — выглядит как «пятьдесят файлов выпало».

На деле **различных** скриптов в обоих заходах ровно 375, а разница — повторные загрузки: обычная
игра переинициализирует часть скриптов, стенд грузит сейв и сразу выходит. Считать надо различные
имена:

```bash
grep -o 'Loading script.*' "$LOG" | sort -u | wc -l
```

Там же второе: `grep -c 'Loading level'` на стенде даёт **ноль**, хотя уровень загружен. Маркер
загрузки называется иначе:

```bash
grep -c '\*\*\* RESET' "$LOG"    # 1 = уровень загрузился и прошёл сброс
grep -c 'total count =  0' "$LOG"  # выход чистый, объекты не потеряны
```

### 🪤 8. Кодировка вывода врёт в самих тестах

`subprocess` без явного `encoding='utf-8'` читает вывод в кодовой странице консоли. Проверки по
русским подстрокам при этом **проваливаются на ровном месте**, а латиница проходит — выглядит как
частичная поломка инструмента. Так четыре проверки в `test_symbolicate` числились сломанными,
хотя инструмент работал.

### ⛔⛔ 9. Спасательная ветка установщика ломала установку ровно у тех, ради кого написана

Найдено 19.08.2026 разбором `install.ps1`. Обработчик негодного ключа доступа звал `Say`, а
`function Say` объявлялась **ниже по файлу**. PowerShell выполняет файл сверху вниз, и функция
существует только после того, как строка с её определением выполнена: вместо «продолжаю без ключа»
человек получал `CommandNotFoundException`, а поскольку внешнего `try` нет и стоит
`$ErrorActionPreference = 'Stop'` — установка обрывалась насмерть.

То есть починка от 16.08, сделанная **ради** тех, у кого рядом остался просроченный `da_token.txt`,
у них же и не работала: вместо внятного 401 стало непонятное «термин Say не распознан».

🪤 Урок шире одного скрипта: в PowerShell **порядок определений — это порядок выполнения**.
Вспомогательные функции объявлять до первого возможного их вызова, включая ветки `catch`.
Проверять разбором, а не запуском успешного пути: успешный путь эту ошибку не проходит вовсе.

### ⚠️ 10. «Отладочных ручек в `user.ltx` нет по построению» — неверно

`13_TESTER_SETTINGS.md` и комментарий в `check_package.py` утверждают, что отладочные ручки в
`user.ltx` попасть не могут: они, мол, все заведены через `CCC_DaDebug*` и не сохраняются. В
поставленном `user.ltx.default` при этом лежит `da_memory_dump 0`, потому что заведена она обычным
`CCC_Integer` — `src/xrGame/console_commands.cpp:4038`, — а такой сохраняется.

Заслон её пропускает по правилу «выключенная ручка вреда не делает», и это правильно. Но
утверждение «по построению» ложное: **чинить надо в точке регистрации**, а не вычищать файл.
🪤 Обратный ложняк рядом: `da_smap_cache` тоже заведена обычным `CCC_Integer`, и это сделано
намеренно — настройка производительности обязана сохраняться.

### ⚠️ 11. Умолчания пакета несут железо разработчика

Шаблон отладочных ключей этого не ловит, потому что ключи штатные. В `user.ltx.default` уезжает
`r__upscaler ui_mm_upscaler_dlss` с `r__render_scale 77`: тестер на AMD или Intel получает в
умолчаниях путь NVIDIA. Там же `rs_c_brightness 1.2` — калибровка под конкретный монитор при
заводском `1.0`.

⚠️ И расхождение, которое ловится только `check_package.py`, но не заслоном: `da_legs_fwd` в
пакете был `-0.3` против `-0.35` в `EXPECT_SETTINGS` — единственное из двадцати ключей. Заслон
смотрит на отладочные ручки, а на согласие с `EXPECT_SETTINGS` — нет; это разные проверки, гонять
надо обе.

### ⛔⛔ 12. `copyfile` теряет дату — и заслон краснеет на символах (20.08.2026)

`shutil.copyfile` копирует содержимое, но **не метаданные**. Разложенный им модуль получает текущее
время вместо сборочного, и проверка символов честно сообщает «карта старше модуля» — сразу по всем
шестнадцати:

```
xrAICore: карта старше модуля
xrCDB: карта старше модуля
...
```

Заслон сверяет модуль с ЕГО картой по времени, с запасом в минуту. Между сборкой и раскладкой
проходит больше минуты — значит любая раскладка через `copyfile` гарантированно красная.

**Всегда `shutil.copy2`** — и при раскладке в игру, и при наполнении `shipped/`. В самом этом
документе в примере шага 5а долгое время стоял `copyfile`, то есть грабли лежали в инструкции.

### ⛔⛔ 13. `_dist/DeadAir-x64-installer.zip` не пересобирается сам (20.08.2026)

В `_dist` лежит архив установщика от прошлой публикации. Если установщик правился, а архив не
пересобран, в выпуск уедет **старая версия** — при том что текст выпуска обещает новые возможности.

Так и вышло: в выпуске оказался установщик, не умеющий ни докачки, ни самообновления, ровно тогда,
когда объявление про них и писалось. Поймано сверкой СОДЕРЖИМОГО, а не даты:

```bash
python -c "import zipfile; s=zipfile.ZipFile(r'_dist/DeadAir-x64-installer.zip').read('install.ps1').decode('utf-8-sig'); print('Update-Self' in s)"
```

Пересобирать архив установщика перед каждой публикацией, из `DeadAir_Update`, и проверять по
характерной строке новой правки.

### ⚠️ 14. Заслон «игра запущена» смотрит на ЛЮБОЙ xrEngine (20.08.2026)

Проверка чистой установки падает с «Игра запущена», если открыт процесс из ДРУГОЙ установки —
например, идёт замер на тестовой сборке. Для игрока с одной установкой это верно, для нас — нет.
Либо закрыть все сеансы, либо отложить пункт 8.2 на потом; убивать чужой сеанс замеров нельзя.

## 4. После выпуска

### Что просить у игрока при вылете

**Только лог** — целиком, не выдержку: в конце служебная таблица `[DA_MODULES]` с базовыми
адресами, без неё смещения не пересчитать, а в начале номер сборки. Дополнительно, если есть:
сохранение, на котором воспроизводится, и что делал перед вылетом.

### Разбор лога

**Шаг 1. Опознать сборку** по первой строке: `OpenXRay Release build 10047 [07d02d134466], …`.
В скобках ревизия — это имя каталога в `D:/DA_symbols/`.

**Шаг 2. Убедиться, что снимок тот** — сверить блок `[DA_MODULES]` с `modules.txt`.
⚠️ Число рядом с адресом — **размер образа в памяти**, а не файла: 86 МБ файла дают 44 МБ образа.

**Шаг 3. Расшифровать:**

```bash
python "D:/Dead Air/xray-16/da_port/tools/symbolicate.py" <лог> --map "D:/DA_symbols/<ревизия>"
```

**Шаг 4. Если снимка нет.** В стеке обычно есть привязка вида `xrFactory_Create() + N byte(s)`.
`RVA_кадра − N` = RVA экспорта у игрока; сравнить с `objdump -p своя.dll`. Не совпало — **любое имя
будет выдуманным**, честнее сказать «не знаю».

⛔ Пересобрать ту же ревизию и разобрать по ней не получится: в бинарник зашиты **абсолютные пути**
исходников, дерево по другому пути даёт другие смещения.

### Приговор по логу: полный набор

Неполный шаблон поиска однажды стоил дня: правка ломала скрипт, а проверка искала не те слова.

```bash
grep -c '^! \[LUA\]'           "$LOG"   # ноль здесь покрывает всё нижеперечисленное
grep -c 'SCRIPT SYNTAX ERROR'  "$LOG"   # скрипт не скомпилировался и выпал ЦЕЛИКОМ
grep -c 'SCRIPT RUNTIME ERROR' "$LOG"
grep -c 'attempt to'           "$LOG"   # обращение к пустоте
grep -c 'FATAL\|stack trace'   "$LOG"
grep -c 'Loading script'       "$LOG"   # столько же, сколько обычно? файл мог выпасть
```

🪤 `attempt to index global 'ИМЯ' (a nil value)` у потребителя означает, что не загрузился **сам
скрипт `ИМЯ`**, а не что ошибка в потребителе.

## 5. Чего в процедуре пока нет

Честный список, чтобы не выглядело завершённым.

- **Отладочная информация не отделена от отгружаемых DLL.** `xrGame.dll` весит 86 МБ, из них около
  двух третей — DWARF, которым рантайм не пользуется. `objcopy --only-keep-debug` сократил бы
  загрузку вчетверо, не мешая разбору.
- **Сохранения игроков не архивируются автоматически.**
- **Кэш шейдеров в отгрузке проверяется только на глаз.** Расхождение стоит перекомпиляции при
  первом запуске, а не ошибки, поэтому в заслон не вынесено.
- **Проверка картинки — только руками.** Стенд сцену не рисует.
