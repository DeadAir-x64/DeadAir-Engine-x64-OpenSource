# Dead Air x64 — документация порта

Перенос мода **Dead Air** (форк Call of Chernobyl для S.T.A.L.K.E.R.: Call of Pripyat) с 32-битного
движка на **OpenXRay** — 64-битный движок с рендером DirectX 11.

Документы писались для человека, который открыл репозиторий впервые и хочет продолжить работу. Они
объясняют ловушки движка и принятые решения; построчные объяснения живут в комментариях рядом с кодом.

## Правила проекта

Четыре вещи, нарушение которых уже стоило времени:

1. **Данные не трогаем.** Конфиги, скрипты и ассеты переносятся из оригинала один в один. Не работает —
   чиним движок. Мод живёт своей жизнью, и правки данных превратятся в конфликт при обновлении.
2. **Правка общего заголовка = пересборка всего.** Иначе часть модулей останется со старым
   представлением о размере класса: игра соберётся, запустится и упадёт где-то ещё.
3. **Все изменения помечаются `[DA_PORT]`** с объяснением **почему**, а не что. `02_PORT_CHANGES.md`
   генерируется из этих меток — рукописный список разошёлся бы с кодом через неделю.
4. **Файлы для правок брать из `appdata/logs/vfs_*`, а не из `extracted/`.** В `extracted/` попали
   устаревшие ревизии: скрипт интерфейса оказался на 1600 байт короче настоящего, XML — без целой
   вкладки. Настоящее содержимое отдаёт только сама игра через свою файловую систему.

## Быстрые команды

Собрать одну цель (около 6 секунд):

```bash
bash _build_fast.sh xrRenderPC_R4
```

Пересобрать список правок после новых `[DA_PORT]`:

```bash
python docs/_regen_changes.py
```

⚠️ **Релизную сборку (`-O3 + LTO`) без выпуска не запускать.** Она идёт долго, а прерванная оставляет
библиотеки нулевого размера, после чего `ninja` отвечает «finished 0s» и врёт. Подробности и правило
про **два набора библиотек** — в [04_PERFORMANCE.md](04_PERFORMANCE.md).

## Что добавил порт сверх оригинала

**Апскейлеры и сглаживание.** TAA, FSR 1/2/3, XeSS, DLSS — выбираются одним пунктом `r__upscaler` в меню
видео. Работает всегда ровно один: включение любого гасит остальные. Под них сделаны честные векторы
движения для всей геометрии, включая скелетную анимацию. FSR 2 при рендере в 70% даёт около +50 fps.

**Потолок теневых источников** `r__light_shadow_budget` — самая дорогая настройка в игре, в стоковом
движке её нет. В баре снимала процессорный рендер с 9.65 до 3.75 мс.

**Масштаб рендера** `r__render_scale`, 25–200%: сцена рендерится меньше окна и растягивается бикубикой
с компенсацией мип-уровней, интерфейс остаётся чётким.

**Вкладка «Производительность»** в настройках: общий пресет плюс все дорогие переключатели,
разложенные по влиянию на скорость.

Плюс экранные отражения в воде и переработанный вид воды — они включены всегда, это часть картины мода.
