# Аудит VERIFY: приговор по каждому месту

`verify_audit.py` находит места, где за `VERIFY`/`VERIFY2`/`VERIFY3` следует разыменование или
индексация. В релизе эти макросы вырезаны целиком, поэтому проверка исчезает, а обращение
остаётся — отсюда и целый класс вылетов (#67, #73, #74, #75).

Список сам по себе — не список дефектов. Правило разбора одно:

> **чинить там, где отказ зависит от ДАННЫХ (конфиги мода, модели, сохранение, сеть), и не трогать
> там, где он зависит от внутреннего порядка вызовов.**

Внутренний инвариант, нарушенный кодом, должен падать — тихий обход спрятал бы настоящую ошибку.

Ниже — приговор по остатку: 33 места вне `net_Spawn` и вне мультиплеера.

## Починено (8)

| Место | Что за ним пряталось |
|---|---|
| `material_manager.cpp:55` | `GetMaterialByIdx` по нашей же защите (#37/#47) отдаёт ноль, а отладочный `Msg` читает у него имя — сообщение роняло игру ровно в том случае, который описывало |
| `ui/UIBuyWndShared.cpp:18` | `sscanf` вернул 0 → цикл берёт `cost[c - 1]`, то есть **`cost[-1]`**. Строка цен — из конфига, хватит опечатки |
| `CarWheels.cpp:80` | `LL_UserData()` = ноль, если у модели машины нет user data; следом `->section_exist` |
| `CarWheels.cpp:379` | то же + `break_torque`/`hand_break_torque` объявлены без инициализации: просто выйти нельзя, тормоза получили бы мусор |
| `moving_bones_snd_player.cpp:129` | имя кости из user data; `LL_BoneID` отдаёт `BI_NONE`, и `LL_GetTransform(BI_NONE)` читает **за концом массива костей каждый кадр** |
| `ParticlesPlayer.cpp:74` | визуал без скелета (в т.ч. молча подставленная заглушка вместо незагруженной модели) → `K->LL_UserData()` по нулю |
| `script_particles.cpp` (весь класс) | система частиц удаляет себя сама, когда доиграла, и обнуляет `m_particles` у владельца **в Lua**; любой следующий вызов из скрипта — по нулю. Пять методов не имели даже `VERIFY` |
| `pp_effector_distance.cpp:14` | не вылет, а тихая порча: `(max - min)` в знаменателе, при равных радиусах из конфига → NaN, а `clamp` его не чинит (сравнения с NaN ложны) |

Отдельно `stalker_animation_manager.cpp:75`: здесь `VERIFY` заменён на **живой `R_ASSERT`**, а не на
мягкий пропуск. Сталкер без анимаций нежизнеспособен, тихо продолжить нельзя — но модель берётся из
профиля персонажа, то есть из данных мода. Раньше такой случай приходил безымянным обращением по
нулю; теперь лог сразу называет НПС и модель.
